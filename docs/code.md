# Code

Python 3.11 or newer, standard library only. The `busnet` package has about 2,500 lines,
the three scripts about 620 more, and the tests about 350. `python3 -m unittest` runs
the tests; see [Checking a change](#checking-a-change).

## Layout

```text
measure.py            measure today's network            -> output/
redesign.py           search for a better network        -> output/redesign/
robustness.py         the results under other trip samples and assumptions -> output/robustness/
busnet.toml           settings: data paths and every assumption
busnet/
  assumptions.py      Assumptions: the default value of every assumption
  config.py           read busnet.toml and --set overrides into Assumptions + data paths
  inputs.py           load every input the settings name (used by all three scripts)
  model.py            read ayna.db into Stop, Route, Pattern, Network; repair defects
  geo.py              distances, flat projection, polylines, stop-to-shape matching
  service.py          run time and fuel per trip; headways; daily service
  population.py       population grid -> (lat, lon, people) zones
  ridership.py        BakuBus daily boardings -> weekday averages
  destinations.py     OpenStreetMap features and metro exits -> destination points, zone pull
  graph.py            stop index; transit graph for door-to-door search
  metrics.py          geometry measures, output tables, door-to-door model, ridership check
  scenarios.py        stop balancing
  optimize.py         redesign: plans, scoring, kinds of change, search
  gtfs.py             write a network as a GTFS feed
tests/                unit tests and a regression test (python3 -m unittest)
data/                 every input, committed (see data.md)
output/               every result, committed and regenerated by the three scripts
docs/                 this documentation
```

`.gitignore` excludes only Python caches (`__pycache__/`, `*.pyc`), virtual environments
(`.venv/`) and macOS `.DS_Store` files. All data and all results are tracked.

## How the pieces fit

```mermaid
flowchart TD
  toml[busnet.toml] --> cfg[config.load_config]
  cfg --> inp[inputs.load_inputs]
  db[(data/ayna.db)] --> model[model.load_network]
  model --> inp
  ext[(data/external, data/headways.csv)] --> inp
  inp --> m[measure.py]
  inp --> r[redesign.py]
  m --> tables[metrics: route_table, detour_table,<br/>trunk_corridors, near_duplicates]
  m --> summ[metrics.network_summary]
  summ --> od[metrics.evaluate_od<br/>over graph.TransitGraph]
  m --> sc[scenarios.balance_stops]
  r --> plan[optimize.Plan, Evaluator]
  plan --> search[optimize.search:<br/>Drop, Straighten, BalanceStops, Shift]
  search --> summ
  r --> gtfs[gtfs.write_gtfs]
  inp --> rb[robustness.py]
  rb --> search
  rb --> od
  rb -. runs redesign.py<br/>with other settings .-> r
```

`load_inputs` returns an `Inputs` object with everything all three scripts need:

| Field | Contents |
|---|---|
| `a` | `Assumptions`: every setting, after `busnet.toml` and `--set` |
| `network` | The repaired `Network` |
| `zones` | Population as `[(lat, lon, people)]`: seven points per hexagon for `measure.py`, one per hexagon for the redesign search (`split=False`) |
| `attraction` | Each zone's pull on trip ends, or `None` without destinations |
| `observed`, `observed_month` | Weekday average boardings per route number, and the month used |
| `supplied` | Real headways from `data/headways.csv` |
| `headways` | `{route id: (minutes, source)}` for every route with stops |
| `points` | Destination points `(lat, lon, weight, kind)` |
| `found`, `data` | Which input files were found, and the data paths from the settings |

## The core objects

| Object | Module | What it holds |
|---|---|---|
| `Stop` | model | `id`, `code`, `name`, `lat`, `lon`, `is_hub` |
| `Route` | model | `id`, `number` (as on the bus), `carrier`, `first_point`, `last_point`, `declared_length_km`, `zone`, `region`, `fare_azn`, `payment`, `card_since` |
| `Pattern` | model | One direction of one route: `route_id`, `direction` (1 or 2), `stop_ids`, `chainage_m` (distance along the path at each stop, from 0), `path` (lat, lon points from the first stop to the last), `path_source` (`shape` or `stops`). `length_m` and `hops()` |
| `Network` | model | `routes` {id: Route}, `stops` {id: Stop}, `patterns` {(route id, direction): Pattern}, `repairs` (list of text). `number(rid)`, `patterns_of(rid)`, `served_stop_ids()`, `routes_at_stop()`, `copy()` |
| `Assumptions` | assumptions | A frozen dataclass with every setting; `cruise_mps(zone)`, `transfer_penalty_s` |
| `Plan` | optimize | A `Network` plus `fleet` {route id: bus-equivalents}. `headways(a)`, `cycle_min(rid, a)`, `total_fleet()`, `stops_of(rid)`, `changed(patterns, drop, fleet)` returns a new plan |

Route ids are AYNA's numeric bus ids; everything inside the code is keyed by them.
`network.number(rid)` gives the number riders see (for example `"7A"`), which is what the
output files show.

## Conventions

- **Units.** Metres and seconds inside calculations; headways and outputs in minutes and
  km where the name says so. Coordinates are (lat, lon) everywhere except GeoJSON, which
  needs (lon, lat).
- **Nothing is edited in place.** Scenarios and plans build new `Network` objects
  (`Network.copy()`, `Plan.changed()`), so before and after can be scored with the same
  functions.
- **Every assumed number is a setting.** If the model needs a value the data does not
  contain, it goes into `Assumptions` and `busnet.toml`, never as a literal in the code.
  (Fixed method choices, such as the 2.5× detour ratio, are function arguments with
  defaults.)
- **Deterministic.** Random sampling uses `random.Random(seed)`; dictionaries and sets are
  sorted before results depend on their order; zip files get a fixed timestamp. The same
  inputs give byte-identical outputs on the same Python version. Python 3.12 changed how
  `sum()` adds floats, so Python 3.11 can differ in the last digits; the regression test
  allows that for CSV and JSON files.
- **Output files.** CSVs are written with `utf-8-sig` and floats rounded to 4 decimals;
  JSON keeps non-Latin letters (`ensure_ascii=False`).
- **Style.** Short docstrings that say what a function returns and why; comments only
  where the code cannot say it.

## Extending the code

### Add an assumption

1. Add a field with its default to `Assumptions` in `busnet/assumptions.py`.
2. Add it to the matching table in `busnet.toml`, with a comment giving its source.
3. Use it as `a.<name>`. `config.py` accepts every `Assumptions` field automatically, and
   rejects names that are not fields.
4. Document it in [configuration.md](configuration.md).

### Add a data input

1. Add a key to `DATA_KEYS` in `busnet/config.py` and its path to `[data]` in `busnet.toml`.
2. Load it in `busnet/inputs.py` through `available(path, name)`, so a missing file is
   reported and recorded in `inputs` of every result.
3. Commit the file under `data/`, add it to `data/fetch_external.py` if it is downloaded,
   and describe it in `data/SOURCES.md` and [data.md](data.md).

### Add a measure

Route-level measures go in `metrics.pattern_metrics` and `metrics.route_table` (one column
of `routes.csv`); network-wide ones in `metrics.network_summary` (one key of
`network.json`). Describe the new column or key in [outputs.md](outputs.md) and its
definition in [methodology.md](methodology.md).

### Add a scenario to measure.py

Write a function in `busnet/scenarios.py` that takes a `Network` and returns
`(new_network, details)` without changing the original, add its name to the `--scenario`
choices in `measure.py`, and call it there like `balance_stops`. `scenario.json` then
compares the full summary before and after.

### Add a kind of change to the redesign

A change is a class with:

- `kind`: a short name, shown in `changes.csv`;
- `routes`: the route ids it touches (may be empty);
- `apply(plan, ctx)`: returns a new `Plan`, or `None` if the change no longer applies (for
  example its route has gone). `ctx` gives `ctx.a` (settings), `ctx.evaluator`,
  `ctx.streets` (the street graph), `ctx.riders` (boardings a day per route: counted where
  known, otherwise estimated), `ctx.observed` (counted boardings by route id) and
  `ctx.protected` (route ids to leave alone);
- `describe(network)`: one sentence for `changes.csv`.

Respect `ctx.protected` unless the change only adds buses. Add candidates of the new kind
in `optimize.candidates(plan, ctx)`, where they are screened alone
and then applied in order of gain, or give them their own step in `optimize.search()`.
The coverage guard, the scoring and the log apply automatically.

### Change what the search optimises

`Evaluator.score()` returns `minutes`, `unreachable`, `within_45` and `changes_2plus`;
`search()` compares `minutes`. To weigh something else (for example operating cost or
people covered), add it to `score()` and change the comparisons in `search()`.

## Checking a change

1. **Run the tests.** `python3 -m unittest` takes about 15 seconds. `tests/test_geo.py`,
   `test_service.py`, `test_config.py` and `test_optimize.py` check `geo.match_stops`,
   the headway rules and daily service, the settings reader, and `Plan` arithmetic on a
   small made-up network (`tests/helpers.py`). `tests/test_regression.py` regenerates
   `output/` with `measure.py` into a temporary folder and compares every file with the
   committed one byte for byte. With `BUSNET_SLOW_TESTS=1` it also regenerates
   `output/redesign/` (about two minutes) and `output/robustness/` (about ten).
2. **Regenerate and compare.** Run the three commands and look at `git diff --stat output/`.
   A refactoring should change nothing; a model change should change only what it means
   to. Commit the regenerated results with the change.
3. **Determinism.** Run twice; the files must be identical.
4. **Calibration.** Network average speed 22 km/h (from `hours_one_trip_each_direction_every_route`
   and `route_km_one_way_total`), implied fleet near 2,300 (`operations.fleet`), and the
   ridership correlation (`ridership_fit`).
5. **Robustness.** After a change to the model or the search, run `robustness.py` and
   check that the redesign's gain is still positive on every trip sample and under every
   setting in `output/robustness/`.
6. **Fresh clone.** Clone the repository into an empty folder and regenerate: the
   results must match the committed `output/` byte for byte, which proves nothing
   depends on files outside git.
7. **GTFS.** Every `stop_id` and `trip_id` must resolve and stop times must increase; the
   MobilityData GTFS validator checks this fully.

A new test goes in `tests/test_<module>.py` as a `unittest.TestCase`; `tests/helpers.py`
builds the two-route network the tests share.
