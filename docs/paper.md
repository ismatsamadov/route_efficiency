# From the repository to a paper

How to turn this work into a research paper as an independent researcher: whether there
is a paper here, what it should contain, where it could be published without paying,
what format journals expect, and the steps from this repository to a submitted
manuscript. Every fact about a journal or publisher below was read on its own pages on
23 October 2026; fees and policies change, so re-check the page before submitting.

## 1. Is there a paper here?

Yes: a **case-study / planning-support paper**. Its contribution is not a new algorithm
but a complete, reproducible pipeline that measures a real bus network from public data
alone, estimates what a fleet-neutral redesign would gain, and quantifies how much that
estimate depends on its own assumptions. Four things in the repository are publishable:

1. the repaired network and its measured diagnosis ([results.md](results.md#todays-network)):
   directness, duplication, detours, stop spacing and coverage, route by route;
2. the door-to-door travel model built only from public data, with its fit against
   observed ridership stated honestly (0.58 fair, 0.77 circular; [fit ladder](results.md#the-demand-model-as-each-input-is-added));
3. the redesign: 51.8 → 50.9 minutes with the same buses, or today's travel times with
   about 12% fewer buses, robust over ten trip samples and eleven alternative
   assumptions ([robustness](results.md#how-robust-the-results-are)), including the
   finding that the strict coverage guard costs nothing;
4. the pipeline itself: every input committed, every output regenerated byte for byte,
   tests, and every assumption in one settings file.

What it is not, and what the paper must say plainly: not a forecast (headways and
demand are estimates), not a methods contribution (a greedy search with no benchmark
comparison), and a description of the network on 6 May 2026, which AYNA has been
changing since January 2026 ([data.md](data.md#when-the-data-is-from)).

One thing reviewers will find: the earlier GitHub report *Baku Public Transit Network
Optimization: Strategic Analysis & Implementation Roadmap* (github.com/analisto/ayna_gov_az,
February 2026, by the same author under the byline "Transport Systems Research Group")
uses the same AYNA data but different definitions and different numbers (an "efficiency
score" of 62.73/100, 46.84% overlap, 41.89% "resource waste", dollar savings). The paper
should cite it and say that this work supersedes it with defined, reproducible measures;
better still, add a note at the top of that README pointing here.

## 2. Three ways forward

**A. Write the case-study paper now.** The repository already contains everything the
paper needs. 6,000–7,000 words, the outline in section 3, the venues in section 4.
Expect two to four weeks of writing and one week of preparing figures and statements.

**B. Strengthen it first, for a stronger venue.** Each item is two to six weeks:

| Addition | Why it helps | Where it would go |
|---|---|---|
| Take a new AYNA snapshot and rerun the three scripts | Shows which findings survive the network AYNA is launching; turns a snapshot into a before/after comparison | [roadmap.md](roadmap.md#next-in-order-of-value), item 7 |
| Metro in the travel graph | Removes the most obvious model gap for Baku | roadmap item 3 |
| Vehicle capacity in the frequency setting | Answers the "you overload busy routes" objection | roadmap item 4 |
| Demand-model calibration with routes held out | Raises the fair 0.58 and makes the validation standard | roadmap item 2 |
| The evaluator on the Mandl and Mumford benchmarks | Needed only if the paper claims anything about the search method | roadmap item 8 |

**C. Pivots and proposals** that reuse the pipeline:

1. **Before-and-after study of Baku's 2026 network reform.** AYNA's new network is
   rolling out now. Measuring the old network (this snapshot) and the new one with the
   same pipeline is a natural experiment few cities offer, and the strongest research
   direction available here. It needs only a second snapshot and the counts for the
   same months.
2. **Accessibility and equity.** Who is within reach of a stop, by district and by
   travel time, before and after the redesign; the population grid, the coverage curve
   and the door-to-door model already support it. Fits the Journal of Transport
   Geography or the Journal of Transport and Land Use.
3. **A data and software paper.** The repaired AYNA snapshot and the first GTFS feeds
   for Baku (`output/redesign/gtfs_today.zip`) as a dataset with a Zenodo DOI, and
   `busnet` as research software in the Journal of Open Source Software (free). JOSS
   publishes papers about software, not results, and asks for an open licence,
   tests and documentation, all of which exist.
4. **A short Findings paper on one result**, for example that the strict coverage guard
   gains as much as the default, or the fit ladder: 1,000 words, three figures.
5. **A proposal to AYNA or BakuBus** for the data in [roadmap.md](roadmap.md#data-to-request-from-ayna-and-the-operators):
   smart-card trip chaining would replace the gravity model and make the redesign
   evaluation far firmer. The proposal can cite the paper as the pilot.

## 3. The paper, section by section

The structure journals expect is introduction, data, methods, results, discussion,
conclusions (IMRaD), with declarations at the end. Each section below names the
repository files it is drawn from.

| Section | Content | From |
|---|---|---|
| Title | e.g. *How efficient are Baku's bus routes? An open-data measurement and a fleet-neutral redesign* | |
| Abstract (150–250 words; TRB wants a structured one: Objectives, Methods, Findings, Novelty, Practical Applications) | The gap, the data, the three results, the robustness, the caveat | [results.md](results.md#in-short) |
| 1 Introduction | No public evaluation of Baku's network existed; AYNA's reform since 2023; what the paper contributes and does not | [research.md §4](research.md#4-bakus-own-programme) |
| 2 Background | Guidelines and other cities' redesigns; the network design problem and why a greedy search is used | [research.md §2, 3, 5](research.md) |
| 3 Data | A table of every source with licence, date and dataset id; the defects and repairs; when the data is from | [data.md](data.md), [data/SOURCES.md](../data/SOURCES.md) |
| 4 Methods | Geometry measures; running time and fuel; headways; population and demand; the door-to-door model; the ridership check; the redesign search; the robustness checks | [methodology.md](methodology.md), [redesign.md](redesign.md) |
| 5 Results | The diagnosis; the redesign and its 27 changes; before and after; the fleet-saving option; robustness; what to check before acting | [results.md](results.md) |
| 6 Discussion | Agreement with AYNA's consultant (17% with limited access against 12.8% beyond 800 m; overlapping routes); limitations; transferability to other cities with only a public map | [roadmap.md](roadmap.md#limitations-of-the-current-version) |
| 7 Conclusions | One paragraph: measurable waste, a cautious redesign returns about a tenth of the fleet, anyone can regenerate it | |
| Declarations | Data and code availability (Zenodo DOI), ethics, competing interests, funding, author contributions, generative-AI use | section 6 below |

Figures (vector PDF or SVG, 300 dpi for raster, each legible in black and white): the
network map with one lens of inefficiency (from `output/redesign/network.geojson`), the
directness and overlap distributions, the coverage curve, the fit ladder, the robustness
plot (gain per trip sample and per setting), and the redesign map. Tables: data sources,
network measures, redesign before and after, the sensitivity table. Every map made from
OpenStreetMap data carries "© OpenStreetMap contributors, ODbL" and the URL
openstreetmap.org/copyright in its caption or a note.

## 4. Where to publish

All checked on 23 October 2026. "Free" means no charge to the author; "hybrid" means
free when the paper is published behind a paywall and paid only if open access is
chosen. Azerbaijan is a Research4Life Group B (low-cost access) country: Elsevier
discounts fully open-access journals by 50% for Group B and by geographical pricing
(45% of the fee to be paid for Azerbaijan) in about 300 titles, but never hybrid ones;
Wiley gives 50%; Sage waives its gold open-access fees fully; Springer Nature and
Taylor & Francis give nothing for Azerbaijan. Elsevier words its eligibility around an
"institution", so an independent author should ask before counting on it.

## 5. Format

- **Structure.** Numbered sections (1, 1.1); an introduction that states the gap and
  the objectives without a long literature survey; methods detailed enough to reproduce;
  results without interpretation; discussion with the limitations; conclusions.
  Appendices A, B with Table A.1 and so on. Acknowledgements and declarations before the
  references (Elsevier) or on the title page (double-anonymised journals).
- **Length.** Case Studies on Transport Policy under 7,000 words; Journal of Transport
  Geography 4,000–6,000; Periodica Polytechnica 8 pages; Transactions on Transport
  Sciences 15 pages; TRB Annual Meeting 20 pages; Findings 1,000 words; Public Transport
  and TRR direct submissions have no limit.
- **References.** Author-year in every venue above (APA 7 at JTLU, TOTS and Findings;
  Chicago author-date at TRR from 30 June 2026; Elsevier applies its own style at proof).
  Give DOIs. Cite datasets as data: author, year, title, repository, version, DOI, with
  "[dataset]" where Elsevier asks for it.
- **Templates.** LaTeX on Overleaf: *Elsevier Article (elsarticle)*, name-year variant,
  for the Elsevier journals; *Springer Nature LaTeX Template* (sn-jnl, author-year
  option) for Public Transport; the *Findings Template*; an unofficial TRB template for
  the Annual Meeting (check it against the current rules). Word is accepted everywhere;
  JTLU requires its Word template after acceptance. Pandoc or Quarto can produce either
  from Markdown, so the docs here can be the first draft.
- **Figures.** Vector (PDF, EPS, SVG) for charts and maps; 300 dpi for raster; Arial or
  Helvetica lettering; readable in grey; one file per figure, numbered; no screenshots.
  OpenStreetMap attribution on every map made from its data.
- **Required statements.** Data availability (with the Zenodo DOI), code availability,
  competing interests ("none"), funding ("no funding was received"), author
  contributions (CRediT roles at Elsevier), ethics (see section 6), generative-AI use
  (JTLU and TRB require disclosure; TRB counts rewriting with AI tools). Elsevier journals
  also want 3–5 highlights.
- **Mistakes editors list.** Opening with a trite sentence about congestion; an abstract
  that repeats the introduction; purely descriptive content with no lesson; undefined
  acronyms in the abstract; PDF as the source file; missing data statement or highlights;
  tables as images; figures inside the Word file; incomplete references; not disclosing
  AI use; submitting to a journal while the same paper is under TRB review.

## 6. Publishing as an independent researcher

- **Yes, you can.** No journal above requires an institution. Write *Independent
  researcher, Baku, Azerbaijan* with an ORCID (0009-0007-7919-4950) and a stable e-mail.
  Elsevier's rights form has the option "Not affiliated to an organization" plus city and
  country; arXiv takes "Independent" as the organization; Springer's Public Transport
  guidelines say unaffiliated authors give only city and country. The MBA at UNEC
  (2024–2026) can be listed only if it is a current formal affiliation.
- **Profiles.** ORCID already exists; add the Zenodo DOI and later the paper to it. A
  Google Scholar profile can be created, but Scholar lists profiles in its people
  search only with a verified university e-mail; the paper itself is indexed anyway.
- **Repository hygiene before anyone cites it.** The repository has no `LICENSE` and no
  `CITATION.cff`. Add a licence for the code (MIT is the usual choice for a standard
  library tool; it covers code only), say in the README which licence each data folder
  carries ([data/SOURCES.md](../data/SOURCES.md)), add `CITATION.cff`, connect the
  repository to Zenodo (log in with GitHub, enable the repository, publish a release
  such as v1.0.0) and cite the **version DOI** of the release that produced the paper's
  numbers. A template for `CITATION.cff`:

  ```yaml
  cff-version: 1.2.0
  message: "If you use this work, please cite it."
  type: software
  title: "Baku bus route efficiency: measurement, travel model and fleet-neutral redesign from open data"
  authors:
    - family-names: Samadov
      given-names: Ismat
      orcid: "https://orcid.org/0009-0007-7919-4950"
      affiliation: "Independent researcher, Baku, Azerbaijan"
  version: 1.0.0
  date-released: 2026-10-23
  license: MIT
  repository-code: "https://github.com/ismatsamadov/route_efficiency"
  keywords: [public transport, bus network, network design, Baku, open data]
  ```

- **Data licences in the paper.** OpenStreetMap: credit "© OpenStreetMap contributors"
  with the ODbL and openstreetmap.org/copyright; the extracted files in
  `data/external/osm/` are a derivative database, which the ODbL allows only under the
  ODbL, so keep them in the public repository with that notice. Kontur Population:
  CC BY, cite "Kontur Population, release 2023-11-01". opendata.az: CC BY datasets are
  cited as Bakı Metropoliteni's with their dataset ids; CC0 needs no attribution but
  give it anyway. AYNA map data: no published licence ([data.md](data.md#the-ayna-bus-network-snapshot-dataaynadb));
  the data-availability statement should say the snapshot was taken from the public
  AYNA map API, is redistributed with attribution as a research snapshot, and that
  AYNA was asked for terms (write to AYNA, and to Bakı Metropoliteni for the counts,
  before submitting; a written permission removes the only legal uncertainty).
- **Ethics.** "This study analysed only publicly available, aggregated, non-personal
  data (bus routes and stops, a population grid, daily boardings per route). No human
  participants were involved and no ethics approval was required." Add "Competing
  interests: none" and "Funding: none".
- **Generative AI.** The documentation in this repository was written with AI
  assistance. Journals increasingly require a statement; write one sentence in the
  acknowledgements wherever the guide asks for it.
- **Peer review.** Expect two reviewers and three to six months to a decision at the
  journals above (TRR and Elsevier use single- or double-anonymised review; JTLU, TOTS
  and Case Studies on Transport Policy double-blind, so remove names and self-references
  from the review copy). Suggest three to five reviewers with institutional e-mails and
  no connection to you, entered in the submission system. Answer every comment point by
  point.

## 7. Step by step

1. Repository: add `LICENSE` (MIT) and `CITATION.cff`; add a licensing section to the
   README; note at the top of the February 2026 GitHub report that this work supersedes
   it; tag release v1.0.0 and get the Zenodo DOI.
2. Write to AYNA and Bakı Metropoliteni for data terms, and request the data in
   [roadmap.md](roadmap.md#data-to-request-from-ayna-and-the-operators).
3. Decide between A, B and C in section 2. For A, take a new snapshot only if it can be
   done within a week; otherwise state the date clearly and list it as future work.
4. Write the paper from section 3, 6,000–7,000 words, figures from `output/`. Ask two
   readers (a transport planner and a quantitative researcher) to comment.
5. Post a preprint: engrXiv (no endorsement needed), or arXiv physics.soc-ph with an
   endorsement; record the DOI in the README and ORCID.
6. Submit, in this order of fit and cost: Case Studies on Transport Policy (subscription
   option, free) or Public Transport (subscription option, free); if a free open-access
   paper matters more than the journal's standing, Periodica Polytechnica Transportation
   Engineering or Transactions on Transport Sciences. Send one sharp result to Findings
   at the same time only if the journals allow it.
7. Prepare the package: cover letter (aims, three findings, fit, novelty, not under
   review elsewhere, preprint DOI, Zenodo DOI), title page with affiliation and ORCID,
   anonymised manuscript where required, highlights, declarations, data statement.
8. After acceptance: add the reference to the preprint, update `CITATION.cff` with
   `preferred-citation`, make a new release if anything changed, add the paper to ORCID.
